# 部署到阿里云 OSS（香港地域）· 操作清单

本项目选定的方案：**阿里云 OSS 香港 + 自有域名，免备案**。
目标是让国内访客有一个**稳定可打开**的入口（实测香港线路 4/4 可达；慢，但不断）。

- 预计耗时：**30～60 分钟**（不含域名实名审核、DNS 生效的等待）
- 花费：**域名年费 + 每月几毛钱的 OSS 按量费用**（新用户免费试用额度只覆盖中国内地地域，香港用不上）
- **不需要 ICP 备案**（香港节点免备案）
- 你只需要准备：阿里云账号、身份证（实名用）、一个域名

> 控制台路径以阿里云官方文档为准；如果界面有出入，搜「阿里云 OSS + 关键字」即可。

---

## 阶段 0 · 买域名前的三个决定

- [ ] **在哪买**：建议就在**阿里云（万网）**买。理由：同账号下把域名绑到 OSS 时可以勾选
      **「自动添加 CNAME 记录」**，省掉「TXT 验证所有权 + 手动加 CNAME」两步；
      而且将来若想备案，境内注册商的域名不用再转移。
- [ ] **买什么后缀**：`.com` 最通用。**务必看"续费价"而不是只看首年促销价**，很多后缀首年几元、续费几十元。
- [ ] **用主域名还是子域名**：建议对外就用**子域名**（如 `news.你的域名.com`），主域名留着以后做别的。
      OSS 绑子域名完全没问题，hash 路由 + 相对路径都不受影响。

- [ ] 1. 注册/登录阿里云，完成**账号实名认证**（个人身份证即可）
- [ ] 2. 域名搜索 → 加购 → 结算（买 1 年即可）

- [ ] 4.（可选）开启自动续费、Whois 隐私保护
- [ ] 5.（可选，但建议现在做）**如果你以后可能想备案**：实名信息要 3 天左右才入库工信部，
      早做完，将来提交备案就不用等

## 阶段 2 · 创建 OSS Bucket（香港）

> ⚠️ **不要买任何 OSS 资源包（存储包 / 流量包 / 请求包）。**
> OSS 是**按量付费，开通即可用，不需要预购**。资源包是"预付费抵扣包"，用来给大用量打折，
> **最小规格就是 100GB 起**——而本站存储只有 **574 KB（0.0006 GB）**、每月流量几百 MB。
> 例如 500GB「标准-同城冗余」包要 **¥171.99**，而同样这点用量按量计费每月只要**几毛钱**。
> 只有当你"按量一年的费用超过包价"时才值得买，本站在这个量级之外，永远用不上。
> （另外：真要买包也必须选**本地冗余（LRS）**并与 Bucket 地域一致，否则不抵扣。）

- [ ] 1. **关于免费额度：香港地域用不上，这步可以跳过。**
      阿里云新用户 OSS 免费试用（20GB 存储 / 2GB 外网流出 / 20 万次请求，3 个月）的地域写的是
      **「中国内地通用」**，官方注释：*"只能抵扣中国内地各地域的对应计费项，不能抵扣中国香港和海外地域的对应计费项"*。
      所以**香港 Bucket 不享受这笔试用额度，本方案是按量计费**。
      想用免费额度就得把 Bucket 建在中国内地，但那必须先备案（要买可备案实例）——为了每月几毛钱花这笔钱不划算。
      按本项目用量，香港按量计费的账单量级见 README 的「费用」小节。
- [ ] 2. 开通 OSS → 创建 Bucket，关键参数：
      - **地域：中国香港**（这是免备案的关键）
      - 名称：全局唯一，小写字母/数字/连字符，如 `ai-news-daily`
      - **存储类型：标准存储** —— 只有它适合对外提供网站访问
      - 存储冗余：**本地冗余（LRS）**（便宜；同城冗余 ZRS 更贵，且创建后不可改）
      - **版本控制：关闭** —— ⚠️ 开启后**无法彻底关闭（只能暂停）**，而本站每天都在覆盖
        `data/news.json`，开了会不断累积历史版本、持续产生存储费用
      - 读写权限：**公共读**
      - 注意：**新建 Bucket 默认开启"阻止公共访问"**，会挡住公共读设置 → 在创建弹窗里直接关掉，
        或创建后到 `权限控制 → 阻止公共访问` 关闭
      - **「Bucket 功能」区的可选项全部保持默认、一个都不要开**：
        服务端加密选**「无」**（本站内容是公开的新闻标题摘要，加密没有意义，选 KMS 还按密钥与调用计费）；
        实时日志查询**不开**（OSS 自带的「用量查询 → 热点统计」免费且足够定位异常流量，需要时再临时开）；
        定时备份**不开**（会额外收费，而 ⚠️ **本站数据本来就提交进 Git 仓库，GitHub 就是现成的备份与版本历史**）；
        HDFS 服务**不开**（面向大数据/AI 数据湖，与静态网站无关）；标签可跳过（只有一个桶没必要）
- [ ] 3. 关闭阻止公共访问：`权限控制 → 阻止公共访问` → 关闭（按提示输入确认文字）
- [ ] 4. 设公共读：`权限控制 → 读写权限 → 设置 → Bucket ACL → 公共读`
- [ ] 5. 开静态网站托管：`数据管理 → 静态页面 → 设置`
      - **默认首页**：`index.html`
      - **子目录首页：不开通** —— 本站是 hash 路由（`#/day/2026-10-08` 这类），浏览器只会请求根路径 `/`；
        而 `assets/`、`data/` 里也没有各自的 `index.html`。这个开关只对「多个独立版块各有首页」
        （如 `/blog/`、`/docs/`）的站点有意义，开通后还要额外配「文件 404 规则」，对本项目纯属多余
      - 默认 404 页：可留空（本站是 hash 路由，正常不会 404）
      - 错误文档响应码：404

## 阶段 3 · 绑自定义域名 + 配 HTTPS

> ⚠️ **顺序很重要**：官方明确要求**先绑定域名，再配置 CNAME 解析**。
> 反过来的话，访问自定义域名时无法正确识别 Bucket，会返回非预期内容。

> 📌 **前置条件：域名必须已经生效**（域名列表里状态是**「正常」**，而不是「注册局审核中」）。
> 原因：CNAME 要域名能解析才有意义；而 **HTTPS 免费证书的签发需要验证域名所有权，域名没生效时申请会失败**。
> 在等域名生效的这段时间，可以先把 **阶段 4 的 CI 配置做完**（完全不依赖域名）：
> 用 OSS 控制台的文件列表，或 `curl -I https://<bucket>.oss-cn-hongkong.aliyuncs.com/data/news.json`
> 返回 200，就说明同步与公共读都已经生效。
>
> 另外：**申请证书前先把最终域名定死**（用主域名还是子域名），免费证书只覆盖你填的那一个域名，
> 之后换域名要重新签。

- [ ] 1. `Bucket 配置 → 域名管理 → 绑定域名`，填 `news.你的域名.com`
      - 域名在**同一个阿里云账号**下 → 直接「确认绑定」，并**勾选自动添加 CNAME 记录**
      - 域名在别的账号 / 别的注册商 → 先用 TXT 记录验证所有权
        （主机记录 `_dnsauth.news`），再手动加 CNAME
- [ ] 2. CNAME 记录值：**绑定成功后，在 `Bucket 配置 → 域名管理` 里复制**
      （已绑定的域名那一行会显示记录值，通常带「复制 CNAME」之类的按钮）——**不是在云解析里**
      官方允许两种值，控制台给哪个用哪个：
      - **CNAME 域名**（推荐，形如 `<bucket>.<region-id>.taihangcda.cn`），绑定后才显示
      - **外网访问域名**，即 Bucket endpoint（如 `latest-ai-news.oss-cn-hongkong.aliyuncs.com`），
        这个在 Bucket 概览页就能看到

      主机记录：子域名填前缀（如 `news`）；**主域名填 `@`**
      - 域名与 OSS **同账号**时，第 1 步勾了「自动添加 CNAME 记录」的话，这一步就已经自动完成了，不用手填；
        若提示主机记录冲突（已有同名 A/CNAME 记录），去云解析删掉旧的再加
- [ ] 3. 等待解析生效（几分钟～几小时），检查：
      ```bash
      dig news.你的域名.com CNAME +short
      ```
- [ ] 4. **配 HTTPS 证书（最容易漏的一步）**：OSS 的默认域名原生支持 HTTPS，
      但**自定义域名必须自己配证书**：
      1. 去**数字证书管理服务**（<https://yundun.console.aliyun.com/?p=cas>）→
         **「个人测试证书（原免费证书）」** 页签。若列表里已有「待申请」的实例，
         直接点操作列的 **「申请证书」**；没有就先创建一个
      2. 申请向导里：
         - **证书绑定域名**：填 OSS 上绑定的那个（如 `latestainews.cn`）。⚠️ **提交后不可修改**
         - **域名验证方式**：**自动DNS验证** —— 域名在阿里云同账号，系统会自动往云解析加 `_dnsauth`
           的 TXT 记录；它只涉及 `_dnsauth` 这个主机记录，**不会动你已有的 `@` CNAME**。
           （选「文件验证」拿不到品牌赠送的 www 域名，而且要求网站已能访问，不划算）
         - **联系人**：必填，选一个或新建（填真实姓名/手机/邮箱，CA 审核与通知用）
         - **所在地**：保持默认（跟随账号）
         - **密钥算法**：保持 **RSA_2048**（兼容性最好，老设备也能握手）
         - **CSR 生成方式**：选**系统生成**
      3. 提交后会进「验证信息」页。**若提示「未检测到 DNS 记录值」**（"自动DNS验证"不一定真的会自动加记录），
         就手动去云解析补这条 TXT：
         `云解析 DNS → 目标域名 → 解析设置 → 添加记录`，按页面给的值填：

         | 字段 | 值 |
         | --- | --- |
         | 记录类型 | **TXT** |
         | 主机记录 | **`_dnsauth`** ⚠️ 只填这一段，**不要**填 `_dnsauth.latestainews.cn` |
         | 记录值 | 粘贴页面给的那串（用「复制」按钮，别带多余空格） |
         | TTL / 解析线路 | 保持默认 |

         等 1~10 分钟后回证书页面点「**验证**」。自查是否生效：
         ```bash
         Resolve-DnsName _dnsauth.你的域名 -Type TXT
         ```
         返回那串值就说明记录已生效。**签发成功后这条 TXT 可以删掉**，不影响证书使用
      4. 回到 OSS：`Bucket 配置 → 域名管理 → 该域名 → 证书托管` → 选择这张证书 → 上传
      5. 验证：浏览器打开 `https://你要用的域名/`，地址栏有安全锁
      - ⚠️ **免费证书不是签一次管一年**（官方公告：单张有效期将陆续缩短至 199 天），
        **到期即中断访问** → 签发后看清实际到期时间，开启证书托管自动续期，或自己记提醒
      - 「申请协助服务」是付费项，不需要
- [ ] 5.（建议）强制 HTTPS：`权限控制 → Bucket 授权策略 → 按语法策略添加`，
      加一条拒绝非加密传输的策略（把 `<bucket-name>` 换成你的桶名）：

      ```json
      {
        "Version": "1",
        "Statement": [{
          "Effect": "Deny",
          "Action": ["oss:*"],
          "Principal": ["*"],
          "Resource": [
            "acs:oss:*:*:<bucket-name>",
            "acs:oss:*:*:<bucket-name>/*"
          ],
          "Condition": { "Bool": { "acs:SecureTransport": ["false"] } }
        }]
      }
      ```

## 阶段 4 · 让 GitHub Actions 自动同步

- [ ] 1. 建 **RAM 子账号**（别用主账号 AccessKey）：
      <https://ram.console.aliyun.com> → 左侧 **身份管理 → 用户** → **创建用户**
      - 登录名称，如 `oss-deploy`
      - **访问方式只勾「使用永久 AccessKey 访问」**，不要勾「控制台访问」（我们只需要 API 访问）
      - 创建后会**一次性弹出 AccessKey ID / Secret，立刻复制保存**——关掉弹窗就再也看不到 Secret 了
      - 然后去 **权限管理 → 授权**，给这个用户加下面的**最小权限策略**（详见本节末尾）
- [ ] 2. 到 GitHub 仓库 `Settings → Secrets and variables → Actions` 配置：

      | 类型 | 名称 | 值 |
      | --- | --- | --- |
      | Secret | `OSS_ACCESS_KEY_ID` | RAM 子账号的 AccessKey ID |
      | Secret | `OSS_ACCESS_KEY_SECRET` | RAM 子账号的 AccessKey Secret |
      | Variable | `OSS_BUCKET` | 桶名，如 `ai-news-daily` |
      | Variable | `OSS_ENDPOINT` | `oss-cn-hongkong.aliyuncs.com`（带不带 `https://` 都行，脚本会自动补）。
      ⚠️ **必须是 `https://`**：如果加了「拒绝非加密传输」的 Bucket Policy，明文 HTTP 会被它拒掉——
      那条策略的 `Principal` 是 `["*"]`，**连 RAM 账号自己也一样被拒**（表现为同步报 `Access denied by bucket policy`） |
      | Variable | `SITE_URL` | 可选：填**实际能打开的**那个地址（如 `https://latestainews.cn/`），让 RSS 自链接指向新域名。
      它只影响 `data/feed.xml` 的 `<link>` 与 `atom:link`，**不会让别的域名变得可访问**——
      想用 `www.你的域名` 得先绑定 www + 加它的 CNAME + 让证书覆盖它 |

      ⚠️ **两类必须放在各自的页签里**：前两个是 **Secret**（加密存储，保存后看不到明文），
      后三个是 **Variable**（明文可见）。**放错页签不会报错，但会静默失败**——
      workflow 读的是两组不同来源（`secrets.OSS_ACCESS_KEY_ID` vs `vars.OSS_BUCKET`）。
      例如把 `OSS_BUCKET` 建在 Secrets 页签，同步时 `oss://$OSS_BUCKET/` 里的桶名就是空的。

- [ ] 3. 手动跑一次验证：仓库 `Actions → 刷新资讯并发布 → Run workflow`
      （`.github/workflows/refresh-and-deploy.yml` 里那一步在没配 secret 时是自动跳过的，
      配好后才会真正执行同步）
- [ ] 4. 检查 Bucket 根目录出现了 `index.html`、`assets/`、`data/`，然后访问你的域名

> 已踩过的坑（都已修复或给出处理办法）：
>
> | 报错 / 现象 | 原因 | 处理 |
> | --- | --- | --- |
> | `chmod: cannot access '/tmp/ossutil/ossutil64'`，步骤 1 秒内失败 | ossutil 的 zip 包里含一层 `ossutil-v1.7.19-linux-amd64/` 目录 | 已改成 `unzip -j` 去层级（workflow 已修） |
> | `Access denied by bucket policy` | 加了「拒绝非加密传输」策略，而 ossutil 走了明文 HTTP；该策略 `Principal` 是 `["*"]`，**连 RAM 账号自己也拒** | 已由 workflow 自动补 `https://` 解决 |
> | `The bucket you access does not belong to you.` | ①RAM 用户**没被授权**这个桶，或 ②AccessKey 属于**另一个阿里云账号** | 见下面「授权核对」 |
> | `OSS_BUCKET 或 OSS_ENDPOINT 为空` | 变量建在了 Secrets 页签 | 移到 **Variables** 页签 |

> **授权核对（对应 `does not belong to you`）**：
> 1. **RAM → 身份管理 → 用户 → 你的子账号 → 权限管理**：必须有策略（自定义的最小权限策略，或临时用 `AliyunOSSFullAccess` 兜底）
> 2. 确认你操作 RAM 时登录的是**拥有这个 OSS 桶的那个阿里云账号**（对比右上角账号名/UID——多账号时最容易踩）
> 3. 自定义策略的 `Resource` 里**两处**桶名都要换：`acs:oss:*:*:latest-ai-news` 与 `acs:oss:*:*:latest-ai-news/*`
> 4. **认证管理**页签里的 AccessKey ID 要与 GitHub Secret 里填的一致
> 5. 快速隔离：先挂系统策略 `AliyunOSSFullAccess` 再跑一次——**变绿**说明是自定义策略写错了（再收紧），
>    **仍报同样错**说明 AK 或账号不对

### 阶段 4 附：RAM 最小权限策略

在 **RAM → 权限管理 → 权限策略 → 创建权限策略 → 脚本编辑**里粘贴下面这段
（把 `latest-ai-news` 换成你的桶名，**两处都要换**），创建一个自定义策略，
再到 **权限管理 → 授权** 把它授权给 `oss-deploy` 用户：

```json
{
  "Version": "1",
  "Statement": [{
    "Effect": "Allow",
    "Action": [
      "oss:ListObjects",
      "oss:GetObject",
      "oss:PutObject",
      "oss:DeleteObject",
      "oss:AbortMultipartUpload",
      "oss:ListParts",
      "oss:GetBucketInfo",
      "oss:GetBucketAcl"
    ],
    "Resource": [
      "acs:oss:*:*:latest-ai-news",
      "acs:oss:*:*:latest-ai-news/*"
    ]
  }]
}
```

> 图省事也可以用系统策略 `AliyunOSSFullAccess`，但那等于**所有桶的完全权限**。
> 这个 AccessKey 要长期放在 GitHub Secrets 里，建议还是用上面这份最小权限。
> 如果同步时报 `AccessDenied`，错误信息里会写出缺哪个 `oss:xxx` 动作，把它补进 `Action` 即可。
